# Contributing

Thanks for helping out. This document describes how we work together on this repo. It's short on purpose — if something here gets in the way of doing good work, raise it and we'll change it.

## Basic guidelines

- Do not delete anyone else's code.

## Quality expectations

- Follow the existing tone and structure of the materials. Run the formatter/linter if there's one for markdown or code (`<add command here>`).
- Examples should compile and run where applicable. Include notes if platform-specific.
- Updates that change explanations or examples should add a test case, runnable snippet, or at minimum a verification step so future contributors can confirm correctness.
- New sections should fit into the flow of the curriculum. Flag any gaps in prerequisites or assumed knowledge.

## Disagreements

Assume good faith and argue the technical merits in the PR or issue thread. If a decision stalls:

1. Try to find a compromise or a smaller version of the change.
2. Ask another maintainer to weigh in.
3. Decisions can be revisited later if needed.

Nobody gets overruled silently, and nobody is expected to keep fighting a lost argument.
